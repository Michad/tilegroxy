= TileJSON
:page-aliases: operation::configuration/tilejson.adoc
:description: Configuration for serving TileJSON documents describing configured layers. 
:page-config-key: server.tilejson
:page-related: operation::tilejson.adoc, forwarded.adoc, server.adoc, layer.adoc

NOTE: See xref:operation::tilejson.adoc[TileJSON operation] for a full description of the endpoints, document structure, and how authentication applies.

== Example
[tabs]
====
YAML::
+
[,yaml]
----
server:
  tilejson:
    enabled: true
    indexpath: tilejson.json
    baseurls:
      - https://tiles-a.example.com/maps
      - https://tiles-b.example.com/maps
----

JSON::
+
[,json]
----
{
  "server": {
    "tilejson": {
      "enabled": true,
      "indexpath": "tilejson.json",
      "baseurls": [
        "https://tiles-a.example.com/maps",
        "https://tiles-b.example.com/maps"
      ]
    }
  }
}
----
====

== Configuration

.Configuration options
[cols="1m,3,1,1,1"]
|===
| Parameter | Description | Type | Required | Default

| Enabled
| If true, serve TileJSON documents for eligible layers
| bool
| No
| false

| IndexPath
| The HTTP path, relative to RootPath, that serves a TileJSON index listing of eligible layer
| string
| No
| tilejson.json

| BaseURLs
| Controls the base(s) used for the `tiles` field, instead of building it from the request. Useful if URLs are opaquely rewritten before reaching tilegroxy, or if tiles are served through multiple hosts. Each entry can include schema, host, and path prefix, and produces one entry in the `tiles` array.
| string[]
| No
| The request's scheme and Host, or what a proxy listed in xref:forwarded.adoc[`server.forwarded.trusted`] reported
|===

.Environment variables
[cols="1m,3m"]
|===
| Configuration Parameter | Environment Variable

| Enabled
| SERVER_TILEJSON_ENABLED

| IndexPath
| SERVER_TILEJSON_INDEXPATH
|===
