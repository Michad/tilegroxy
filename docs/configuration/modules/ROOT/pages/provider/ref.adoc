= Ref
:page-aliases: operation::configuration/provider/ref.adoc
:description: Ref refers requests to another layer. 
:page-eyebrow: Provider
:page-config-name: ref
:page-related: provider/index.adoc[Provider Overview], layer.adoc, provider/blend.adoc, operation::layer-patterns.adoc

== Description

This provider allows you to re-use layers to avoid repeating yourself, most useful in advanced/complex use cases in conjunction with layer patterns.

Ref has a recursion limit of 10. We attempt to detect cycles and chains that will violate this limit at startup, but not all cases can be statically detected. At runtime, a request that reaches the same layer name twice results in an error as soon as it repeats, and any other chain results in an error after the 10th hop. This protection only applies to recursive ref's in a single config, for example there is no protection against using a proxy provider between two separate instances of tilegroxy.

If this provider is used from a layer utilizing xref:operation::layer-patterns.adoc[layer pattern], you can include `+{layer.NAME}+` placeholders in the `layer` field to fill in the matching pattern segments. If using this feature, datatype, bounds, and other metadata, as well as cyclical dependencies, can't be inferred. 

== Example
[tabs]
====
YAML::
+
[,yaml]
----
provider:
  name: ref
  layer: something_else
----

JSON::
+
[,json]
----
{
  "provider": {
    "name": "ref",
    "layer": "something_else"
  }
}
----
====

== Configuration

.Configuration options
[cols="1m,3,1,1,1"]
|===
| Parameter | Description | Type | Required | Default

| layer
| The layername to refer towards, treated the same if it were supplied in an incoming request. Can contain `+{layer.NAME}+` placeholders
| string
| Yes
| None
|===
