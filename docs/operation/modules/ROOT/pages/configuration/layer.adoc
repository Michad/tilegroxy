= Layer

A layer represents a distinct mapping layer as would be displayed in a typical web map application.  Each layer can be accessed independently from other map layers. The main thing that needs to be configured for a layer is the provider described below.

The URLs of incoming requests follow a format like: `+/tiles/{layerName}/{z}/{x}/{y}+` the layer name can be one of two things: 1) the ID of the layer or 2) A string that matches a pattern.  A pattern should include non-subsequent placeholder values wrapped in curly braces. Those placeholder values can be used in certain providers, such as the Proxy provider where they can be forwarded along to the upstream map layer. To understand how you can utilize patterns, see the link:/examples/configurations/noaa_post_storm.yml[NOAA Post-Storm example]

When using a pattern you can include https://regex101.com/[Regular Expressions] to validate the values that match against the placeholder.

It is highly recommended that layer names be alphanumeric plus underscores. While other characters aren't forbidden, several mechanisms (some caches and telemetry) replace potentially dangerous characters with underscores. This can lead to collisions if you have layer names that differ only by special characters.

Configuration options:

[cols="1,3,1,1,1"]
|===
| Parameter | Description | Type | Required | Default

| id
| A url-safe identifier of the layer. Primarily used as the default path for incoming tile web requests
| string
| Yes
| None

| pattern
| A url-safe pattern with non-subsequent placeholders
| string
| No
| id

| paramValidator
| A mapping of regular expressions to use to validate the values that match against the placeholders. Each expression must match the full value (it's automatically anchored to start and end). Specify a key of "*" to apply it to all values
| map[string]string
| No
| None

| provider
| The configuration that drives how tiles are generated
| xref:configuration/provider/index.adoc[Provider]
| Yes
| None

| client
| A Client configuration to use for this layer specifically that overrides the Client from the top-level of the configuration. See below for Client schema
| xref:configuration/client.adoc[Client]
| No
| None

| skipcache
| If true, skip reading and writing to cache
| bool
| No
| false

| skipanalytics
| If true, skip recording xref:configuration/analytics/index.adoc[analytics] events for this layer. Useful for internal or debugging layers you don't want cluttering usage data
| bool
| No
| false

| allowcoalesce
| Whether to allow concurrent requests for the same tile to be combined into one tile generation call. This includes requests triggered by different users. If your tiles are customized per user/tenant, you will want to set this false. See xref:../howto/user-dynamic.adoc#_coalesce[this how-to] for further information
| bool
| No
| Auto (based on the layer's cache and provider)

| cachecontrol
| Overrides the `Cache-Control` block from xref:configuration/server.adoc[Server] for this layer. The override applies field by field, so a layer that specifies one directive keeps the rest of what the server configured
| xref:configuration/cache_control.adoc[Cache Control]
| No
| None


| description
| Defines a description of this layer for metadata purposes. Currently has no effect unless TileJSON is enabled. Some providers may supply a default if unset here
| string
| No
| None

| attribution
|  Defines an attribution of this layer for metadata purposes. Currently has no effect unless TileJSON is enabled. Some providers may supply a default if unset here
| string
| No
| None

| center
| Specified as a triplet of longitude, latitude, zoom. Defines a center (or representative) point of this layer. Also used by the xref:commands/test.adoc[test command] to pick a default tile. Some providers may supply a default if unset here
| float[]
| No
| None

| vectorlayers
| Only valid for vector data types. Defines the sub-layers inside the tiles matching the tilejson `vector_layers` format (`id`, `fields`, `description`, `minzoom`, and `maxzoom`). Currently only used for metadata purposes and has no effect unless TileJSON is enabled. Some providers may supply a default if unset here.  
| Object[]
| No
| None

| datatype
| Declares what type of tiles this layer returns. This is inferred from the provider when possible. If this contradicts the provider (for example datatype is raster but the provider always produces vector tiles) startup fails. Required if it can't be inferred and a feature relying on it (such as bounds) is used. Also determines the data type of xref:configuration/error.adoc[error responses] for this layer
| string, one of: raster, mvt
| No
| Taken from the provider

| minzoom
| Requests for a zoom level below this are rejected as out of bounds
| int
| No
| Taken from the provider if it supplies one, otherwise no lower limit

| maxzoom
| Requests for a zoom level above this are rejected as out of bounds
| int
| No
| Taken from the provider if it supplies one, otherwise no upper limit

| bounds
| Restricts this layer to a geographic area. When set, the layer's provider is automatically cropped (via xref:configuration/provider/crop.adoc[crop] or xref:configuration/provider/cropmvt.adoc[cropmvt]). This requires the layer's data type to be resolvable
| Object with north, south, east, west
| No
| Whole world

| examples
| A list of example layer names that fulfill the pattern. Used for xref:configuration/tilejson.adoc[TileJSON] documents and the xref:commands/test.adoc[`tilegroxy test`] command. Has no effect on a layer identified by a plain `id`
| string[]
| No
| None

| cacheversion
| A version identifier used to invalidate cache entries (does not delete the cache entries). Cache entries are prefixed with this identifier, so when this changes no pre-existing cache entries ever match. It's recommended to treat this as a serial version number.
| string
| No
| None

| cache
| The ID of one of the xref:configuration/cache/index.adoc[caches] to use for this layer instead of the default.
| string
| No
| The default cache
|===

Example:

----
layer:
  id: my_layer
  pattern: my_{name}_{version}
  examples:
    - my_first_v2
    - my_second_v9
  paramValidator:
    "*": "^[a-zA-Z0-9]+$"
    "version": "v[0-9]{1,3}"
  skipCache: true
  client:
    userAgent: my_app/1.0
  minzoom: 4
  maxzoom: 18
  bounds:
    south: 51
    north: 63
    west: -7
    east: 0.1
  provider:
    ...
----
