= Configuration
:description: Tilegroxy is a configuration driven application. This page describes the conventions shared by every part of the configuration. Configuration can be supplied as either YAML or JSON format. Examples are shown in both YAML and JSON, and advanced YAML features are avoided to make it easy to convert between them.

NOTE: See the xref:configuration/index.adoc[Configuration Reference] for every available option and xref:examples/index.adoc[Examples] for complete configurations explained line by line.  More link:https://github.com/Michad/tilegroxy/tree/main/examples/configurations[examples are available in the repository].

== Conventions

Parameter names (configuration keys) are case-insensitive unless indicated otherwise.

Names (see below) are always lower case.

Unknown or misspelled configuration keys are rejected as an error rather than silently ignored, both at the top level and within any entity block. See xref:commands/config_check.adoc[Config Check] for details.

Some parameters can be specified by environment variables which must be upper case. Environment variables override config parameters which override default values.

The environment variable name is derived by joining the parameter's full key path with `_`, upper-cased. For example, `server.port` becomes `SERVER_PORT` and `logging.main.level` becomes `LOGGING_MAIN_LEVEL`. This works for any scalar parameter with a fixed key, even if it's not set in your config file at all. It does not apply to the dynamic, per-entity parameters described in <<entities>>, which support `env.ENV_VAR_NAME` value substitution instead.

== Entities

Some configuration sections (xref:configuration/authentication/index.adoc[authentication], xref:configuration/provider/index.adoc[provider], xref:configuration/cache/index.adoc[cache], xref:configuration/datastores/index.adoc[datastores], xref:configuration/analytics/index.adoc[analytics], xref:configuration/ratelimit/index.adoc[ratelimit] and xref:configuration/secret/index.adoc[secret]) support selecting different methods of operation that change the full list of parameters available. For example,  a "proxy" provider requires a `url` parameter to get a map tile from another server while a "static" provider takes in a `image` to return for every request. You select these operating modes using a parameter called `name`. 

Since these entities are too dynamic to have fixed environment variables and frequently may require a secret to operate, any string parameters can be made to use an environment variable by specifying a value in the format of `env.ENV_VAR_NAME`.  You can also use an external secret store xref:configuration/secret/index.adoc[if configured] by specifying a value in the format `secret.SECRET_NAME`. 

== Structure

The following is the top-level configuration structure. All top-level keys are optional besides `layers`:

[,yaml]
----
server: ... # <1>
health: ... # <2>
client: ... # <3>
logging: ... # <4>
telemetry: ... # <5>
error: ... # <6>
secret: ... # <7>
authentication: ... # <8>
cache: ... # <9>
defaultcache: some-id # <10>
datastores: # <11>
  - ...
analytics: ... # <12>
ratelimit: ... # <13>
defaultratelimit: some-id # <14>
layers: # <15>
  - ...
----
<1> xref:configuration/server.adoc[Server]: how the HTTP server operates
<2> xref:configuration/health.adoc[Health]: health check endpoints served on a separate port
<3> xref:configuration/client.adoc[Client]: how requests to upstream HTTP servers are made
<4> xref:configuration/log.adoc[Log]: application, access, and audit logs
<5> xref:configuration/telemetry.adoc[Telemetry]: OpenTelemetry metrics, logs, and traces
<6> xref:configuration/error.adoc[Error]: how errors are returned to users
<7> xref:configuration/secret/index.adoc[Secret]: an external store for sensitive values
<8> xref:configuration/authentication/index.adoc[Authentication]: how incoming requests are authenticated
<9> xref:configuration/cache/index.adoc[Cache]: where tiles are stored, either a single cache or a list of them
<10> xref:configuration/cache/index.adoc#overridable-caches[Default cache]: the ID of the cache layers use unless they specify another
<11> xref:configuration/datastores/index.adoc[Datastores]: shared connections used by caches, providers, authentication, analytics, and rate limiting
<12> xref:configuration/analytics/index.adoc[Analytics]: where usage events are recorded
<13> xref:configuration/ratelimit/index.adoc[Rate Limit]: how many tiles can be requested in a period
<14> xref:configuration/ratelimit/index.adoc[Default rate limit]: the ID of the policy layers use unless they specify another
<15> xref:configuration/layer.adoc[Layers]: the layers to serve
