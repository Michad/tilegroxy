= Rate Limit
:description: Shows how much of each rate limit rule a user, tenant, or IP address has used, and can reset it. Useful for answering support questions and checking how close a customer is to their quota.
:page-eyebrow: Command
:page-command: tilegroxy ratelimit

NOTE: This reads the store configured under xref:configuration/ratelimit/index.adoc[ratelimit] directly, so it works against a running deployment. It only connects to the datastore the store uses, not to any providers or caches. It can't be used with the memory store since those counters only exist inside the server process.

== Usage

Full, up-to-date usage information can be found with `tilegroxy ratelimit -h`.

.Output of `tilegroxy ratelimit -h`
[,text]
----
Shows the current count for each rate limit rule that applies to the
given user, tenant, IP address, and layer, along with the limit after
overrides and when the count resets.

Rules come from the policies given with --policy, or the policy of the
layer given with --layer, including the policies they extend. Without
either, every policy is shown.

Supply the same values a tile request would have. A user or tenant left
out is empty, the same as a request without one. A rule needing an IP
address or layer you didn't supply is skipped with a warning.

For a rolling period, Used is the same weighted estimate the check uses.

Pass --reset to set the matching counters back to zero instead. For a
rolling period this clears both the current and previous bucket.

Usage:
  tilegroxy ratelimit [flags]
----

== Flags

.Flags
[cols="1,1,1,3"]
|===
| Flag | Type | Default | Description

| `-h`, `--help`
| bool
| `false`
| help for ratelimit

| `--ip`
| string
|
| The client IP address to look up

| `--json`
| bool
| `false`
| Output in JSON

| `-l`, `--layer`
| string
|
| The ID of the layer to look up. Selects the layer's policy unless --policy is given. Required by rules segmented by layer

| `-p`, `--policy`
| strings
|
| The ID(s) of the policies to look up. Every policy by default

| `--reset`
| bool
| `false`
| Set the matching counters back to zero

| `--dry-run`
| bool
| `false`
| Only usable with `--reset`. Display what rules will be reset

| `--tenant`
| string
|
| The tenant ID to look up

| `--user`
| string
|
| The user ID to look up
|===

== Example

Using the policies from the xref:configuration/ratelimit/index.adoc#example[configuration reference example]:

[,shell]
----
tilegroxy ratelimit -c tilegroxy.yml -p premium --tenant acme --user alice
tilegroxy ratelimit -c tilegroxy.yml -p premium --tenant acme --reset
----

In Kubernetes, the simplest way to run this is inside an existing pod, which already has the configuration and access to the store:

[,shell]
----
kubectl exec deploy/tilegroxy -- tilegroxy ratelimit -c /tilegroxy/config/tilegroxy.yml -p premium --tenant acme --user alice
----

The first command produces an output like:

[,text]
----
Rule                    Used      Limit      Remaining    Resets
standard.user.1s        12        50         38           1s
premium.tenant.month    812345    5000000    4187655      2026-11-01T00:00:00Z
----
